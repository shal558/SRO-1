## «Маршруты между учебными корпусами»

### 1. Введение

В рамках проекта была разработана информационная система «Маршруты между учебными корпусами», предназначенная для хранения информации об учебных корпусах университета и определения маршрутов между ними.

Для реализации проекта использовались графовая база данных Neo4j и язык программирования Python. Графовая модель позволяет представить учебные корпуса в виде узлов, а маршруты между ними — в виде связей. Такой подход упрощает хранение данных и поиск путей между объектами.

Проект реализован с использованием библиотеки Neo4j для Python, а также инструментов VS Code и Neo4j Sandbox.

### 2. Цель проекта

Цель проекта — разработать приложение для хранения информации об учебных корпусах университета и поиска маршрутов между ними с использованием графовой базы данных Neo4j.

### 3. Задачи проекта

Для достижения поставленной цели были выполнены следующие задачи:

1. Изучить особенности графовых баз данных и их применение.
2. Создать модель данных для хранения учебных корпусов и маршрутов.
3. Настроить подключение Python-приложения к Neo4j.
4. Реализовать создание, просмотр, изменение и удаление учебных корпусов.
5. Реализовать создание и изменение связей между корпусами.
6. Разработать алгоритм поиска кратчайшего маршрута.
7. Подготовить тестовые данные и заполнить ими базу данных.
8. Проверить работу основных функций приложения.

### 4. Используемые технологии

В ходе разработки проекта использовались следующие технологии:

- **Python** — язык программирования для реализации логики приложения.
- **Neo4j** — графовая база данных для хранения учебных корпусов и маршрутов.
- **Cypher** — язык запросов для взаимодействия с графовой базой данных.
- **Visual Studio Code** — среда разработки Python-приложения.
- **Neo4j Sandbox** — среда для подключения к графовой базе данных.
- **pytest** — инструмент для автоматического тестирования приложения.
- **python-dotenv** — библиотека для загрузки настроек подключения из файла `.env`.

### 5. Проектирование базы данных

Для реализации проекта была выбрана графовая модель данных.

В базе данных используются два основных элемента:

**Узел Building** — представляет учебный корпус университета.

Для каждого корпуса хранятся следующие свойства:

- `id` — уникальный идентификатор корпуса;
- `name` — название корпуса;
- `address` — адрес или расположение;
- `floors` — количество этажей.

**Связь CONNECTS** — представляет маршрут между двумя учебными корпусами.

Для связи используются следующие свойства:

- `distance` — расстояние между корпусами;
- `time` — время прохождения маршрута.

Графовая модель позволяет хранить маршруты непосредственно между корпусами и выполнять поиск соседних объектов и кратчайших путей.

### 6. Архитектура приложения

Приложение состоит из нескольких основных компонентов.

**Python-приложение** выполняет обработку пользовательских операций, проверяет входные данные и формирует запросы к базе данных.

**Neo4j Driver** обеспечивает подключение Python-приложения к Neo4j и выполнение Cypher-запросов.

**Neo4j Database** хранит узлы учебных корпусов и связи между ними.

**Seed Script** используется для первоначального заполнения базы данных тестовыми данными.

**Tests** предназначены для проверки корректности работы основных функций приложения.

Общая схема взаимодействия:

Python Application → Neo4j Driver → Neo4j Database

### 7. Реализация проекта

Основная логика приложения находится в файле `app.py`.

В приложении реализован класс `RouteApp`, который содержит методы для работы с учебными корпусами и маршрутами.

#### 7.1. Подключение к базе данных

Для подключения используется драйвер Neo4j.

Настройки подключения хранятся в файле `.env`. Это позволяет отдельно задавать адрес базы данных, имя пользователя и пароль.

Метод `verify_connection()` проверяет возможность подключения к Neo4j.

При успешном подключении приложение выводит сообщение:

`Connection to Neo4j: OK`

#### 7.2. Создание ограничений

Метод `create_constraints()` используется для создания ограничений базы данных.

Ограничения помогают обеспечить уникальность идентификаторов учебных корпусов и предотвратить появление дубликатов.

#### 7.3. Создание учебного корпуса

Метод `create_building()` добавляет новый учебный корпус в базу данных.

Перед созданием объекта проверяются его данные. Для хранения корпуса используется узел `Building`.

Каждый корпус имеет уникальный идентификатор, название, адрес и количество этажей.

#### 7.4. Просмотр учебных корпусов

Метод `get_building()` позволяет получить информацию об отдельном корпусе по его идентификатору.

Метод `list_buildings()` выводит список всех учебных корпусов, содержащихся в базе данных.

Это позволяет проверить, какие объекты были добавлены в систему.

#### 7.5. Изменение учебного корпуса

Метод `update_building()` используется для изменения информации об учебном корпусе.

С его помощью можно обновить название корпуса, адрес или количество этажей.

Изменение выполняется непосредственно в базе данных Neo4j.

#### 7.6. Удаление учебного корпуса

Метод `delete_building()` удаляет учебный корпус из базы данных.

При удалении корпуса также удаляются связанные с ним маршруты, чтобы не оставлять в графе связи с отсутствующими объектами.

#### 7.7. Создание маршрутов

Метод `create_connection()` используется для создания связи между двумя учебными корпусами.

Для маршрута задаются расстояние и время прохождения.

В проекте предусмотрено создание связей в обоих направлениях, поэтому маршрут между двумя корпусами может использоваться для перемещения туда и обратно.

#### 7.8. Изменение и удаление маршрутов

Метод `update_connection()` позволяет изменить параметры существующего маршрута.

Метод `delete_connection()` удаляет связь между корпусами.

Это обеспечивает возможность обновления маршрутной сети при изменении расстояния или времени прохождения.

#### 7.9. Поиск соседних корпусов

Метод `neighbors()` используется для поиска корпусов, непосредственно связанных с выбранным объектом.

Результат содержит информацию о соседних корпусах и параметрах маршрутов.

Данная функция позволяет определить, куда можно перейти из выбранного корпуса без поиска полного пути.

#### 7.10. Поиск кратчайшего маршрута

Метод `shortest_hop_route()` предназначен для поиска маршрута между двумя учебными корпусами.

При поиске учитывается количество переходов между узлами графа.

Приложение определяет последовательность корпусов, через которые можно пройти от начального объекта к конечному.

Также выводятся количество переходов, общее расстояние и время прохождения найденного маршрута.

#### 7.11. Ранжирование маршрутов

Метод `ranked_routes()` используется для получения нескольких вариантов маршрута.

Результаты позволяют сравнить доступные пути между учебными корпусами.

При анализе маршрутов можно учитывать количество переходов, расстояние и время прохождения.

### 8. Заполнение базы данных

Для первоначального заполнения базы данных используется файл `seed.py`.

Скрипт автоматически добавляет тестовые учебные корпуса и маршруты.

В проекте подготовлено:

- 10 учебных корпусов;
- 15 пар маршрутов;
- 30 направленных связей.

Маршруты создаются в обоих направлениях.

Для добавления объектов используется механизм `MERGE`, который позволяет находить существующие объекты и не создавать дубликаты при повторном запуске скрипта.

После выполнения скрипта база данных содержит тестовую графовую структуру, необходимую для проверки приложения.

### 9. Запуск приложения

Для запуска проекта используется Visual Studio Code и терминал PowerShell.

Сначала необходимо установить зависимости проекта:

`pip install -r requirements.txt`

После установки зависимостей необходимо настроить файл `.env`, указав параметры подключения к Neo4j.

Затем выполняется заполнение базы данных:

`python seed.py`

После успешного заполнения запускается приложение:

`python app.py`

При запуске приложение проверяет подключение к базе данных, выводит список учебных корпусов и демонстрирует поиск маршрутов.

### 10. Тестирование проекта

Для проверки работоспособности приложения использовался инструмент pytest.

Тестирование включало проверку корректности входных параметров и ограничений поиска маршрутов.

В ходе тестирования были проверены следующие случаи:

1. Проверка недопустимых параметров маршрута.
2. Проверка корректности ограничения количества переходов.
3. Проверка корректности ограничения при поиске кратчайшего маршрута.

Для запуска тестов используется команда:

`python -m pytest tests -v`

По результатам тестирования все три теста завершились успешно.

Также была выполнена дополнительная проверка операций создания, чтения, изменения и удаления учебных корпусов и маршрутов.

В ходе проверки подтверждена возможность выполнения основных CRUD-операций.
